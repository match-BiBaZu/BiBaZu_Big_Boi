A transient before initialization finishes is distinct from a flag that remains asserted after startup. The adapter waits for initial valid data with outputs disabled; subsequent invalid data or startup timeout latches PLC fault 3. ## Fault 3 diagnosis and correction

`MAIN.ConveyorServoFaultCode = 3` is the adapter's latched **EtherCAT/feedback fault**, not an EL7201 diagnostic number. During the reported fault, both terminals had `InfoState = 8` (OP), `WcState = FALSE`, `FeedbackInvalid = FALSE`, and `Statusword = 96` (`0x0060`, drive fault bit clear). Both controlwords and velocity targets were zero. The PLC's `ConfigLoaded` flag was still false. These observations are consistent with the original adapter latching invalid data before EtherCAT startup completed; there is no historical trace proving the exact triggering scan.

A 2.2-second read-only trace also showed encoder positions varying by only 16 and 24 counts, while instantaneous velocity estimates varied from -8746 to +8883 and -12761 to +10497 raw units. The original single-sample velocity threshold could reject a stopped reset or prevent a completed move from settling despite nearly stationary encoders.

The corrected adapter waits for 100 ms of continuously valid feedback at initial startup, keeping both drive outputs disabled. Failure to qualify within five seconds latches fault 3. After initial qualification, any communication/feedback interruption immediately latches fault 3 and disables both drives; returning data cannot clear it automatically.

Configuration capture, stopped reset, and move/stop settling now use both encoder position traces. Each motor must remain within 0.05 motor full steps (0.09 degrees, approximately 262 mapped counts at this resolution) of a fixed reference for 100 ms. Movement outside either window restarts qualification for both. Invalid data discards the window, and changing encoder resolution starts a new one. Raw velocity remains available for diagnostics. Finite travel still requires both motors within the target-position tolerance and a further 100 ms settling interval.

After installing the correction, leave conveyor Enable and calibration mode off while feedback qualifies. A subsequent latched fault requires healthy data, stopped encoders, and a fresh GUI Reset. Reset cancels previous motion commands and cannot start the belt; starting requires a separate command. A fault reported in a terminal's own CoE diagnostic object must be interpreted separately from this PLC code.

## Values that must be commissioned

The current machine source initializes `ConveyorServoCommissioned = TRUE` with the verified values above. `GuiConveyorEnabled = FALSE` and `GuiConveyorCalibrationMode = FALSE` keep both motors disabled at startup. For a different motor, roller, or mounting arrangement, disable commissioning and repeat the following checks before changing the saved machine settings.

1. **Motor setup:** use the stationary CoE procedure below for each connected AM8112. This requires no NC axis or motion-axis library.
2. **Operating mode and feedback scaling:** verify `7010:03 = 9` (CSV), actual mode `6010:03 = 9`, and `8000:12 = 20`, `8000:13 = 12`. These verified values are included in each terminal's XAE Startup list. With this position format, use `1048576` mapped counts per motor revolution for `ConveyorServoFeedbackCountsPerRev` and `ConveyorServoFeedbackCountsPerRev2`. The motor's native encoder resolution is a different quantity. [Beckhoff position scaling](https://infosys.beckhoff.com/content/1033/el72x1-001x/3170742667.html)
3. **Velocity factors:** read `9010:14` on **each** drive and configure `ConveyorServoVelocityUnitsPerRevPerSec` and `ConveyorServoVelocityUnitsPerRevPerSec2`. Beckhoff's no-NC guide defines this factor as command units for one revolution per second, which also matches the installed ESI unit. Another Beckhoff CSV overview says rpm; therefore verify commanded speed against encoder displacement and elapsed time at low speed before increasing it. Do not assume a factor of `268435`. [Beckhoff no-NC commissioning](https://infosys.beckhoff.com/content/1033/el72x1-001x/1859316107.html)
4. **Direction and ratio:** set `ConveyorServoDirection1` and `ConveyorServoDirection2` to `+1` or `-1` only after checking their physical belt directions. No gearbox is installed, so the initial `ConveyorServoMotor2Ratio = 1.0` applies when the effective drive roller circumferences are equal. Otherwise the required motor-2/motor-1 revolution ratio is `circumference1 / circumference2`. The physical mounting may require opposite motor signs.
5. **Belt calibration:** the compatibility interface defines **200 virtual full steps per motor-1 revolution**, with **64 virtual increments per full step**. Set `ConveyorServoCalibratedMmPerFullStep` to measured belt travel per motor-1 revolution divided by `200`, or use the existing GUI's two-marker calibration during supervised commissioning. The PLC publishes this value through `GuiConveyorMmPerFullStep` and `GuiConveyorCalibrationValid`; writes from old profiles cannot replace it. Normal continuous motion is blocked until this new scale is positive. Calibration jogs use virtual steps and can run before distance calibration, once the drive commissioning gate is satisfied.
6. **Motion limits:** tune the speed limit, acceleration, position gain, and synchronization/following tolerances for the belt and load. The `300 rpm`, `300 rpm/s`, and tolerance/gain values are configuration limits, not demonstrated loaded performance. Begin supervised operation with a low GUI speed or short calibration jog. A change to the frozen drive settings requires a stopped reset. Startup now qualifies feedback automatically with outputs disabled; fault 3 after its timeout or after a later interruption requires a stopped explicit reset as described above.

On a PLC restart/download these variables return to the verified source defaults above. Later online tuning or marker-calibration changes must be recorded and incorporated into the machine configuration to survive a restart. The adapter uses a common motion trajectory with encoder corrections and mismatch monitoring. It does not implement a torque-sharing controller, so mechanical alignment, roller ratio, drive tuning, and current sharing must be checked under load.

## Verification before normal use

Build the PLC in XAE so its TMC/process image is regenerated, then confirm every servo link resolves to the current **Gerät 1 (EtherCAT)** tree. Check that no hardware link addresses `MAIN.Stepper*`; unrelated I/O mappings are preserved by this change and need their normal project validation. During supervised low-speed commissioning, verify paired start, forward/reverse, normal stop, finite GUI jogs, marker/distance reporting, and the automatic conveyor sequence. Test that a fault or loss of usable data from either drive stops the pair, and that reset requires a fresh command before motion resumes. Check synchronization and braking behavior under the intended load before increasing speed.

Ordinary GUI Stop, speed/direction changes, and calibration exit request a controlled deceleration; completion waits for both encoder positions to reach the trajectory and remain within their standstill windows. Drive faults, unusable feedback after startup, and the existing reorientation abort/heartbeat latch disable both drive outputs. Reset cancels outstanding GUI motion commands. The reorientation heartbeat remains active for its existing owner; the adapter does not add a new heartbeat contract to the legacy setup or image-capture GUI.

The pressure-I/O links discovered in the scanned project were corrected: `MAIN.RawNozzlePressure` and `MAIN.RawNozzlePressure2` now use `AI Standard Channel 1/2 / Value` on EL3068, rather than its status words. Nozzle-array permits and pressure setpoints now start off/zero until a GUI supplies the desired settings, preventing startup sensor events from firing a nozzle.

Diagnostic `MAIN.ConveyorServoFaultCode`: `1` invalid/uninitialized configuration, `2` drive fault, `3` invalid EtherCAT/encoder data, `4` enable timeout, `5` synchronization error, `6` following error or lost operation enable, `7` move/stop timeout, `8` configuration changed, `9` reset timeout, `10` invalid command.
